# 双服务运行与维护

功能服务是唯一业务数据所有者。它校验用户权限、范围、版本和预算，保存查询证据、图片、研究日志及提议，并负责原子采用和撤销。Agent 执行服务不打开 SQLite，通过带独立服务凭据的内部 HTTP 接口领取任务和提交结果。卡片提取保留在功能服务，不依赖 Agent/Harness。

## 执行和中断

内部协议版本为 1。任务在 SQLite 中记录，Agent 领取时获得随机租约，每约 5 秒续约，默认 15 秒失联即中断。任务包括研究、浏览器、图片下载/处理和释放资源。不同类型有独立并发限制。当前使用短轮询领取任务，不依赖 Redis。

每次工具调用、预算申请与日志写入带操作 ID，功能服务验证请求摘要并返回已保存回执。重复 HTTP 请求不会重复执行已提交操作；取消、超时和过期租约拒绝新的回调。研究提议仅在模型结束及日志刷新后对用户开放采用。

功能服务重启后将旧执行任务标记中断，不恢复旧回调，也不自动重试付费研究。Agent 重启会失去浏览器页面句柄；应用已保存的正文、截图和图片仍可读取，新研究使用新任务。数据库仍受单应用进程锁保护。

浏览器的临时页面和查询缓存在 Agent 内存中；查询结果与二进制截图经接口验证后由功能服务持久化。正文证据 ID 统一绑定功能服务的查询 ID。图片转换与缩略图生成在 Agent 执行，功能服务验证回执、去重并保存最终资产；中转附件消费后删除。

## 配置与服务隔离

默认功能服务公开地址为 `127.0.0.1:4317`，内部执行接口为 `127.0.0.1:4319`，Agent 健康检查为 `127.0.0.1:4318/health`。健康检查不包含模型密钥和业务资料。

服务凭据至少 32 字符，安装时随机生成，支持 `TRAVEL_SERVICE_TOKEN_FILE`。首次管理员注册还需要独立安装凭据，避免局域网其他设备抢先注册。`PUBLIC_URL` 控制浏览器来源校验与 HTTPS Cookie，`TRUST_PROXY` 只信任实际代理。

原生安装使用两个 LaunchAgent，程序位于带版本的 `releases/`，`current` 指向当前版本，数据不在程序目录内。重复执行安装器保留配置与数据，并在切换程序前备份已有数据库。`--no-start` 只在指定安装目录生成副本和 plist，不操作登录服务，供验收使用。升级前执行备份；原开发数据库需显式备份恢复到新安装，避免误用私人测试数据。

Docker 使用两个运行目标和三个卷：`app-data`、`agent-data`、`service-config`。只有功能服务挂载 `app-data`；首次安装凭据放在该卷的私有目录，Agent 只能读取服务凭据卷。Compose 等待 app 健康后启动 Agent，并检查 Agent 是否已连接。容器内 Chromium 通过显式环境开关关闭自身 sandbox，仍由非 root 用户和容器隔离运行；不用于访问任意未经许可的网址。

## 构建和发布

`vendor/deepseek-harness.lock.json` 固定上游提交。bootstrap 使用冻结 pnpm 锁安装，准备运行产物；运行时使用相对路径清单，无须 Git 或开发机器的 `.cache`。备份日志校验器打包为单独兼容模块，功能服务不加载完整 Harness。

当前原生安装从源码构建，再复制运行依赖，安装体积约 1.5 GB；尚未优化依赖裁剪或提供签名的预编译安装包。首次构建可能需要 Git/编译工具与网络，后续启动不需要源码目录。没有接入应用自动升级，使用 `git pull --ff-only` 后再次运行安装脚本。

GitHub CI 执行测试和 Docker 运行验收；`v*` 标签工作流发布 app、agent 两个 GHCR 镜像。首次推送前需要仓库写入权限，首次公开镜像的可见性由 GitHub Packages 设置决定。
